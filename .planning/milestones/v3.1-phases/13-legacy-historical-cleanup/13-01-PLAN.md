# Plan 13-01: Legacy SQLite, Vercel & Historical DuckDB Removal

## Objective
Remove all remnants of `sql.js`, SQLite WASM workers, seed fixture SQLite generation, Vercel deployment configs/references, and `historical.duckdb` dependencies. Ensure the application is 100% powered by `streaming.duckdb` directly and builds cleanly.

## Key Changes
1. **Remove SQLite / sql.js**:
   - Uninstall/remove `sql.js` and `@types/sql.js` from `package.json`.
   - Remove `postinstall` script copying `sql-wasm.wasm`.
   - Delete `public/sql-wasm.wasm`.
   - Delete `src/lib/workers/db.worker.ts`.
   - Remove `sql.js` exclusion from `vite.config.ts`.
   - Remove `sql.js` from `tests/regression/global-setup.ts` and remove or update `tests/unit/seed-fixture.test.ts`.
2. **Remove `historical.duckdb` dependency**:
   - Update `src/lib/streamingClient.ts`: All candle requests (both sub-second and standard timeframes 1m-1D) query `streaming.duckdb` directly. No historical DB fallback or blending.
   - Refactor `src/lib/db.ts` and `src/hooks/useDatabase.ts` to remove OPFS/SQLite logic, relying cleanly on streaming DuckDB status.
   - Update `backend/streaming_service/duckdb_client.py`: Remove `historical.duckdb` requirement; default strictly to `streaming.duckdb`.
3. **Remove Vercel References**:
   - Remove Vercel references in docs and configs.
   - Ensure clean `npm run build` and `npm test`.

## Verification
- `npm run build` succeeds without `sql.js` or WASM errors.
- `npm test` runs with zero `sql.js` or `historical.duckdb` errors.
