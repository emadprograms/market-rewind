# Phase 18-01 Plan: Single-Candle Reliability & Initial Data Load Guards

## Objective
Eliminate the intermittent single-candle loading bug by guarding against query boundary anomalies, preventing premature initial render while loading, and eliminating the effectiveCutoff race condition.

## Requirements Covered
- DATA-01: Non-replay initial load defaults to unbounded display
- DATA-02: Automatic query retry on anomalous single-bar responses
- DATA-03: Render suppression guard in chart lifecycle during initial loading
- DATA-04: Diagnostic warning when data filtering reduces bar count anomalously

## Proposed Changes

### 1. `src/hooks/useChartData.ts`
- Enhance `load()` function to validate query responses:
  - If `timeframe !== '1D'` and `data.length === 1`, log warning and issue a fallback query with unbounded `endTime`
  - If retry returns more bars, use that data
- Add diagnostic telemetry:
  - If `localMasterData.length > 1` but `filteredData.length <= 1`, log detailed diagnostic object showing `effectiveCutoff`, `timeframe`, `showEth`, `isReplayMode`, `globalTime`

### 2. `src/hooks/useChartLifecycle.ts`
- In `useEffect` data update handler:
  - If `chartData.length === 1 && isLoadingHistory`, suppress `setData()` to prevent transient single-candle flicker while full history is streaming in.

### 3. `tests/unit/singleCandleReliability.test.ts`
- Write comprehensive unit tests for:
  - `effectiveCutoff` evaluation logic
  - Single-candle retry logic in `useChartData`
  - Lifecycle suppression guard when loading history
  - Diagnostic warning triggers
