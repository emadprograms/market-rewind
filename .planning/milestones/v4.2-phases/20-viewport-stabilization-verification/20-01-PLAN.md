# Phase 20-01 Plan: Viewport Interaction Stabilization & Comprehensive Automated Verification

## Objective
Ensure buttery-smooth user mouse dragging, panning, and zooming while playback is active, remove redundant logical range sets that fight pointer velocity, verify the decoupled 1D price line, and create a comprehensive automated test suite validating speed, interaction, and data reliability.

## Requirements Covered
- VIEW-01: Viewport synchronization does not override or fight user mouse dragging/panning during playback
- VIEW-02: 1D extended-hours price line updates without causing lifecycle re-renders
- VIEW-03: Automated tests verify smooth playback, non-blocking interaction, and single-candle prevention
- VIEW-04: Zero regression across all test suites and production build

## Proposed Changes

### 1. `src/hooks/chart/useChartViewport.ts` (VIEW-01)
- In `syncViewport()`:
  - Eliminate redundant `ts.setVisibleLogicalRange(oldLogicalRange)` calls when `shift === 0` or when `wasAtEnd === false`.
  - When the user has panned into history, do not touch the logical range during data sync. Lightweight-charts natively preserves the view.

### 2. Comprehensive Test Suite `tests/unit/playbackViewportInteraction.test.ts` (VIEW-01, VIEW-02, VIEW-03)
- Write tests verifying:
  - Viewport logical range is preserved when user pans into history during playback.
  - `setVisibleLogicalRange` is never called redundantly with identical range coordinates during mouse drag.
  - 1D extended-hours price line updates via `createPriceLine` / `applyOptions` without triggering `useChartLifecycle` re-renders.
  - Panning while playback is active preserves user's view offset without snapback.

### 3. Full Verification & Milestone Completion (VIEW-04)
- Run all unit and integration test suites.
- Verify production build.
- Perform milestone audit against all requirements.
