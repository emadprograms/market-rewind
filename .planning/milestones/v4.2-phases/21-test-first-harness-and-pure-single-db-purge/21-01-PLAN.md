# Phase 21-01 Plan: Test-First Harness & Pure Single-DB (`streaming.db`) Backend Purge

## Objective
Establish the diagnostic test harness replicating all defects identified in `market-rewind-diagnosis-and-plan.md`, verify their failure against the existing code (Red phase), and purge `historical.duckdb` completely from the backend so that all candles are generated exclusively from `streaming.duckdb` using DuckDB `time_bucket()`.

## Requirements Covered
- **TEST-01**: Diagnostic Vitest Test Suite replicating all 9 failure modes
- **TEST-02**: Diagnostic Playwright E2E Suite verifying end-to-end browser manifestations
- **TEST-03**: Red Phase Execution Verification: confirm diagnostic tests fail predictably
- **DATA-01**: Pure `streaming.duckdb` Architecture: completely remove `historical.duckdb` from backend and server
- **DATA-02**: Dynamic High-Performance Aggregation: build all candles solely from raw `ticks` in `streaming.duckdb`
- **DATA-03**: Strict Session Isolation in DuckDB Queries: intraday and 1D session boundary enforcement
