# Plan 41-01: Backend Service Migration & Order Flow Tape

## Objective
Migrate `DuckDBService` and `server.py` to route all operations through `TickLakeReader`, retiring direct `streaming.duckdb` file attachment while preserving all public REST/WebSocket API contracts, adding reverse-chronological order flow tape queries with spread calculation, and providing structured 503 handling during lake maintenance.

## Context & Constraints
- **Zero API Breaking Changes**: The React frontend expects `/api/candles`, `/api/ticks`, `/api/symbols`, `/api/summary`, and `/api/status` to retain their existing response shapes.
- **Order Flow Tape**: Time & Sales requires reverse-chronological order with computed `spread` (`ask - bid`).
- **Maintenance 503 Handling**: During off-hours compaction when `_maintenance/in_progress.json` exists, HTTP handlers must respond with HTTP 503 and retry advice rather than crashing.

## Tasks

### Task 1: Add Reverse-Chronological Tape Query to `TickLakeReader`
1. Implement `query_tape(symbol: str, limit: int = 50) -> List[Dict[str, Any]]`:
   - Resolve recent date partitions for the symbol in descending date order.
   - Read files from the latest active date partition.
   - Execute vectorized DuckDB query:
     ```sql
     SELECT
         timestamp,
         symbol,
         coalesce(price, bid_price) AS price,
         coalesce(volume, 1.0) AS volume,
         coalesce(bid, bid_price) AS bid,
         coalesce(ask, ask_price) AS ask,
         CASE WHEN bid IS NOT NULL AND ask IS NOT NULL THEN round(ask - bid, 4) ELSE NULL END AS spread,
         source,
         session,
         ingest_id
     FROM read_parquet(?, hive_partitioning=false)
     ORDER BY timestamp DESC, ingest_id DESC
     LIMIT ?
     ```
   - Return formatted tape records with `timestamp`, `symbol`, `price`, `volume`, `bid`, `ask`, `spread`, `source`, `session`.

### Task 2: Refactor `DuckDBService` in `backend/streaming_service/duckdb_client.py`

4. Update `get_symbol_summary(symbol)`:

### Task 3: Update `backend/streaming_service/server.py`

2. In `/api/ticks`, support `direction=desc` to utilize `query_tape` with spread calculations.
3. Update `/ws/playback` to stream genuine Parquet ticks ordered by timestamp.
