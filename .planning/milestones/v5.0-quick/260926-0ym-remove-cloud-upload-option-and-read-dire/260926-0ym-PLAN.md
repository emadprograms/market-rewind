# Quick Plan: Remove Cloud Upload Option & Read Directly from streaming.db

## Objective
Remove all file upload and cloud upload UI elements, inputs, and fallback upload prompts from the application. Configure the frontend to connect directly to the active DuckDB streaming database service (`streaming.duckdb` / `streaming.db` from `data-harvester` running on port 8000) without any user upload requirements. Document and clarify the purpose of the `backend/` folder in `market-rewind`.

## Tasks

### Task 1: Eliminate Upload UI Elements and Upload Handlers
- **Files**: `src/components/Sidebar.tsx`, `src/App.tsx`, `src/hooks/useDatabase.ts`, `src/index.css`
- **Action**:
  - Remove `UploadCloud` icon, `<label className="upload-zone">`, file input, and `handleFileUpload` prop from `Sidebar.tsx`.
  - Remove legacy external DB release links in `Sidebar.tsx` (the GitHub releases download links for old `.db` files).
  - Add a dedicated streaming DB connection badge/indicator in `Sidebar.tsx` showing connection status.
  - In `App.tsx`, remove `handleFileUpload` prop passing and replace the empty state ("Please upload your database file...") with a streaming connection prompt ("Please ensure DuckDB streaming service is active at localhost:8000").
  - In `useDatabase.ts`, remove `handleFileUpload` and remove `loadDatabaseFromFile` references.
- **Verify**: Component compiles cleanly, no broken prop types, tests pass.

### Task 2: Configure Direct Streaming from DuckDB Service (localhost:8000)
- **Files**: `vite.config.ts`, `src/lib/streamingClient.ts`, `src/hooks/useDatabase.ts`
- **Action**:
  - In `vite.config.ts`, update proxy target to `http://localhost:8000` (with fallback/env support) so all `/api` calls route to the live DuckDB harvester service.
  - In `src/lib/streamingClient.ts`, normalize status response to handle both `streaming` and `streaming_db` formats, adapt `getSymbols()` to support `data-harvester`'s `{ symbols: [...] }` structure, and route tick/tape queries through `/api/stream/tape` or `/api/ticks`.
  - In `src/hooks/useDatabase.ts`, prioritize direct DuckDB connection and display live tick/symbol metrics in the status bar.
- **Verify**: `npm test` passes, `curl http://localhost:8000/api/status` integrates cleanly with client schema.

### Task 3: Comprehensive Verification, Build Check, and Backend Folder Clarification

  - Run all Vitest tests and production build (`npm run build`).
