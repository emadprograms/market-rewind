# Quick Task: Playback Performance Tests & Fixes

## Problem Statement

The playback update pipeline feels sluggish — updates appear to happen ~1x/second instead of reflecting the actual tick arrival rate (which can be 3-10+ ticks/second during active trading). Root cause analysis identified 3 concrete issues:

### Issue 1: O(n) Recomputation Per Animation Frame
`filteredData` and `chartData` useMemos in `useChartData.ts` have `globalTime` as a dependency. Since `globalTime` changes at 60fps, every frame triggers:
- `new Date().getTime()` on 10,000+ historical bars (filteredData filter)
- `resampleData()` with `new Date()` on all filtered bars
- Linear scan of 19,000+ symbolTicks for bucket ticks
- `useChartLifecycle.ts` effect runs `chartData.map(d => new Date().getTime())` on all bars again + sort

### Issue 2: Tick Batching Swallows Individual Updates
`advanceSimulationTime` processes ALL ticks within a frame's time window (~16ms at 1x) in a single `set()` call. Only the last tick per symbol survives in `latestTickBySymbol`.

### Issue 3: Frame Drop Cascade
Heavy per-frame computation (Issue 1) causes frames to take 50-200ms instead of 16ms. The next rAF fires late with a larger `dtWallMs`, causing even bigger time jumps and more tick batching.

## Tasks

### Task 1: Write Unit Tests for Performance Issues
**Files:** `tests/unit/playbackPerformance.test.ts`
**Action:** Create unit tests that:
1. Measure `filteredData` computation time with 10,000+ bars — assert it stays under 5ms
2. Measure `chartData` computation time — assert under 5ms
3. Verify `advanceSimulationTime` with multiple ticks in 16ms window correctly updates latestTickBySymbol for each symbol
4. Test that the chart update effect (useChartLifecycle) uses incremental update() not setData() during replay
5. Test that `resampleData` performance stays under 10ms for 10,000 bars

### Task 2: Write Playwright E2E Test for Visual Update Rate
**Files:** `tests/e2e/playbackUpdateRate.spec.ts`
**Action:** Create Playwright test that:
1. Starts a replay session on a date with known tick data
2. Plays at 1x speed for 5 seconds
3. Monitors console logs for `[useChartData chartData]` messages
4. Asserts that chart updates happen at least 10 times per second (not 1/sec)

### Task 3: Fix the Update Pipeline
**Files:** `src/hooks/useChartData.ts`, `src/hooks/useChartLifecycle.ts`
**Action:**
1. Split `filteredData` into a stable historical portion (only recalculates on localMasterData/timeframe change) and a lightweight live-edge check
2. Cache Date parsing results — avoid `new Date()` in hot loops
3. In `chartData` memo: use binary search instead of linear scan for symbolTicks bucket lookup
4. In `useChartLifecycle.ts`: only call `update()` on the forming candle during replay, not rebuild the entire formatted array
