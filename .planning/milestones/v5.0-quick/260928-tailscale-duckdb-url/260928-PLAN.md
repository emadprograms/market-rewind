# Quick Task: Configurable DuckDB Streaming Service URL

## Problem Statement
When running Market Rewind on client devices or accessing it over Tailscale (e.g., `http://100.x.y.z:3000` or `http://my-desktop:3000`), the application currently defaults to or expects DuckDB streaming service on `localhost:8420`. On client devices, the DuckDB streaming service is not running locally—it is running on the host/workstation machine on port 8420.

Users need:
1. A smart default URL that automatically matches the hostname accessed in the browser with port 8420 (`http://${window.location.hostname}:8420`).
2. The ability to enter and change the DuckDB streaming URL from any client device, persisted across reloads in `localStorage`.
3. An interactive connection card on the main screen when disconnected, with pre-filled inputs, quick-fill host presets, and connection testing.
4. An always-accessible connection status and configuration dialog in the sidebar.

## Plan

### Task 1: Dynamic URL Resolution & Storage (`src/lib/streamingClient.ts`)
- Implement `getDefaultStreamingUrl()` and `getDefaultWsUrl()` using `window.location.hostname` when in browser context.
- Implement URL normalization (`normalizeServiceUrl`) to handle missing protocols (`http://` default), trailing slashes, and derive corresponding WebSocket URLs (`ws://`, `wss://`).
- Implement `localStorage` persistence (`market_rewind_duckdb_url`).
- Refactor `StreamingClient` class to use dynamic getters `getBaseUrl()` and `getWsUrl()` instead of static module constants.
- Add `streamingClient.setServiceUrl(url)` with event listener support (`onServiceUrlChange`).
- Add pre-flight connection test method `checkConnection(url: string)`.
- Fix the existing variable scoping bug for `fallbackEndpoint` in `getCandles`.

### Task 2: Database Hook Reactivity (`src/hooks/useDatabase.ts`)
- Track active streaming URL in state.
- Listen for URL changes from `streamingClient` and trigger automatic reconnection and symbol re-fetching.
- Expose `serviceUrl`, `changeServiceUrl`, and detailed connection status.

### Task 3: Interactive Disconnection Screen (`src/App.tsx`)
- Replace the static `"Please ensure DuckDB streaming service is running at localhost:8420"` message with an interactive `ConnectionSetupCard` when offline.
- Features:
  - Editable URL input pre-filled with the smart default (`http://${window.location.hostname}:8420`) or stored URL.
  - Quick-preset chips: `Current Host (${window.location.hostname}:8420)` and `Localhost (http://localhost:8420)`.
  - Connect & Test button with testing state and error diagnostics.

### Task 4: Sidebar Connection Dialog (`src/components/Sidebar.tsx` & `src/components/ConnectionModal.tsx`)
- Allow clicking the database status icon in the sidebar to open a connection settings dialog at any time.
- Display current status (Connected/Offline), tick counts, latency/health, and input to update the backend URL on the fly.

### Task 5: Comprehensive Tests
- Add unit tests in `tests/unit/streamingUrlConfig.test.ts`:
  - Test smart default resolution (`window.location.hostname` $\rightarrow$ port 8420).
  - Test URL normalization (`localhost:8420`, `http://...`, `https://...`, trailing slashes).
  - Test WebSocket URL mapping (`http:` $\rightarrow$ `ws:`, `https:` $\rightarrow$ `wss:`).
  - Test `localStorage` saving, reading, and clearing.
  - Test `StreamingClient` dynamic URL changes, listeners, and API endpoint construction.
- Run `npm test` and `npm run build` to verify integrity.
