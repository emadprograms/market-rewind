# Quick Task: Time-Based Playback Scrubber Slider

## Problem Statement
The bottom scrubber slider in `PlaybackBar.tsx` is currently tick-based (`min={0}`, `max={totalTicks - 1}`, `value={currentTickIndex}`). In financial replay:
1. Tick density is highly non-linear: pre-market (e.g. 9:20am - 9:30am) has very few ticks compared to regular market hours (which have tens of thousands of ticks).
2. Users cannot scrub to a meaningful time (e.g., preparing at 9:20am, then scrubbing to 9:29am or 9:30am to trade the open).
3. The scrubber shows meaningless tick counts (`1204/50000`) instead of trading session time.
4. `seekTickTime` in `usePlaybackStore.ts` used `Math.abs(tMs - targetMs)`, which picked future ticks when seeking between ticks, violating temporal isolation and causing `advanceSimulationTime` to get stuck when resuming from 9:29am.

## Requirements
1. The bottom slider must be time-based (linear in Unix ms / seconds), spanning from the session start time (`minTime`) to the session end time (`maxTime`).
2. The slider value must be bound to `currentTime`.
3. Scrubbing to 9:29am or 9:30am must position the replay state to that exact time, applying only ticks that occurred at or before that timestamp.
4. When playback is resumed after scrubbing to 9:29am or 9:30am, simulation time advances continuously and seamlessly into subsequent ticks.
5. Next to the slider, a clean time label must show session time progress (e.g., `09:29:00 / 16:00:00` in the session ticker's timezone), with tick information available in tooltips.
6. Comprehensive unit and integration tests verifying time-based scrubbing, 9:20am pre-market preparation, 9:29am/9:30am seek & continue, and temporal isolation.

## Plan
### Task 1: Accurate Temporal Seeking Engine (`src/store/usePlaybackStore.ts`)
- Refactor `seekTickTime` to use binary search $O(\log N)$ to find the last tick at or before `targetMs` (`isoToMs(tick.time) <= targetMs`).
- If `targetMs < firstTickMs`, set `currentTickIndex = -1`, `currentTick = null`, `latestTickBySymbol = {}`, `currentTime = targetMs`.
- Scan backwards from target index to update `latestTickBySymbol` in $O(1)$ amortized time for fast, 60fps scrubbing without CPU stutter.
- Ensure `advanceSimulationTime` works with `currentTickIndex = -1` when replay advances from pre-market into the first market tick.

### Task 2: Time-Based Playback Slider Component (`src/components/PlaybackBar.tsx`)
- Compute `minTime` and `maxTime` dynamically from `bufferedTicks` / `masterData` and initial `currentTime`.
- Bind `<input type="range">` to `min={minTime}`, `max={maxTime}`, `step={1000}` (1 second), `value={sliderValue}`.
- Trigger `seekTickTime(Number(e.target.value))` on change.
- Format time display label next to the slider showing `HH:MM:SS / HH:MM:SS` in the session ticker's timezone.
- Add `data-testid="playback-time-slider"` and `aria-label="Time-based playback slider"`.

### Task 3: Comprehensive Unit & Integration Tests
- Add tests in `tests/unit/timeBasedSlider.test.tsx` testing the `PlaybackBar` slider rendering, bounds, value binding, and time scrubbing.
- Add tests in `tests/unit/timeSeekingPlayback.test.ts` testing pre-market preparation at 9:20am, scrubbing to 9:29am and 9:30am, continuing playback forward, and rewinding.
- Update helper in `tests/regression/mocks/replayJourney.ts` if needed to support both time-based format and tick info.
