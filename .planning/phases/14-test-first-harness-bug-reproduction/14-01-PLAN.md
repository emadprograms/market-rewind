# Plan 14-01: Test-First Harness & Bug Reproduction Specs

## Objective
Author a comprehensive test suite (both Playwright E2E specs and Vitest integration/unit tests) specifically reproducing the user-reported issues:
1. Date Reset Bug: Selecting holiday/weekend dates (e.g. Sept 7, 2026) must not load future ticks (Sept 24/25).
2. Multi-Asset Playback Freeze: Clicking PLAY must update all open charts (e.g. AAPL and AMD) in real time.
3. Group Switching Playback: When a chart is set to AMD via group, it must receive live AMD updates rather than freezing or receiving session ticker updates.
4. Genuine Tick Replay: Assert replay buffer loads true DuckDB ticks (thousands of ticks) without 4-micro-tick synthesis or 4,200 bar caps.

## Proposed Test Files
1. `tests/regression/replay/dateResetIsolation.test.ts`: Vitest test asserting date reset temporal isolation on holidays and standard trading days.
2. `tests/regression/replay/dateReset.spec.ts`: Playwright E2E spec verifying date reset in the UI.
3. `tests/regression/sync/multiAssetPlayback.test.ts`: Vitest test asserting multi-ticker playback state synchronization.
4. `tests/regression/sync/multiAssetPlayback.spec.ts`: Playwright E2E spec verifying concurrent multi-chart replay (AAPL + AMD).
5. `tests/regression/sync/groupPlayback.spec.ts`: Playwright E2E spec verifying grouped chart updates during replay.
6. `tests/unit/realTickPlayback.test.ts`: Vitest test asserting true tick streaming without 4200 cap.

## Verification
- Run `npm test` and `npx playwright test` to see tests correctly establish the contracts and assertions.
