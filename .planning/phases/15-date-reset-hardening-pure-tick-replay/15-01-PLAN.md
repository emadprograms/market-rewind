# Plan 15-01: Date Reset Hardening & Pure Tick Replay

## Objective
Harden the replay engine and date reset behavior:
1. Ensure all tick queries are strictly bounded within `[startTime, endTime]` and eliminate any fallback to unconstrained live feeds or future dates (`REPLAY-01`).
2. Provide explicit status messaging and UI indicators when a selected date has 0 trading ticks (e.g., market holidays such as Labor Day Sept 7, 2026, or weekends), preventing ghost data or foreign date loads (`REPLAY-02`).
3. Completely remove `synthesizeTicksFromBars` and artificial 4,200 bar caps from the tick loading pipeline; stream genuine DuckDB ticks directly into the playback buffer (`REPLAY-03`).

## Implementation Steps
1. **`src/App.tsx`**:
   - Remove `synthesizeTicksFromBars` import and usage.
   - Remove synthetic gap-filling logic that was fabricating micro-ticks.
   - In `loadStreamingTicks`, query `streamingClient.getTicks` with `startTime` and `endTime`.
   - If `ticks.length === 0`:
     - Set `bufferedTicks` to `[]`.
     - Anchor `currentTime` to canonical 9:20 AM ET for that date.
     - Set `isPaused` to `true`.
     - Set a clear warning/notice or status state indicating market holiday / no ticks recorded.
   - If `ticks.length > 0`:
     - Load genuine raw DuckDB ticks into `setBufferedTicks(ticks)`.
     - Seek `currentTime` to 9:20 AM ET or the first tick.
2. **`src/components/PlaybackBar.tsx`**:
   - If `bufferedTicks.length === 0`, display `Market Closed (No Ticks)` or disable Play button cleanly with explanatory tooltip/status.
3. **`src/lib/tickSynthesizer.ts`**:
   - Deprecate/remove `synthesizeTicksFromBars`, keep `buildCandleFromTickSlice` for live candle aggregation.
4. **Verification**:
   - Run Vitest suite: `npm test`
   - Run Playwright suite: `npx playwright test`
   - Ensure `TEST-01`, `TEST-04`, `REPLAY-01`, `REPLAY-02`, `REPLAY-03` pass completely.
