# Phase 19-01 Plan: Decoupled Playback State & O(1) Incremental Chart Updates

## Objective
Decouple high-frequency playback ticks from the React render tree so that ~60fps playback ticks update lightweight-charts directly via O(1) `series.update()` without triggering React re-renders, array filtering (`filteredData`), or array resampling (`resampleData`).

## Requirements Covered
- PERF-01: Decouple high-frequency playback store subscriptions from React render tree
- PERF-02: Direct O(1) lightweight-charts series updates for forming candles
- PERF-03: Eliminate redundant O(N) array filtering and resampling during active playback
- PERF-04: Candle bucket boundary commit throttling

## Architecture & Implementation Steps

### 1. Direct Playback Candle Updater in `useChartLifecycle.ts` (PERF-02, PERF-04)
- Add a direct external Zustand store subscription in `useChartLifecycle.ts` (matching `trading-terminal`'s pattern):
  - Subscribes to `usePlaybackStore.subscribe(...)`.
  - Tracks `lastCandleRef` initialized from the latest completed bar of `chartData`.
  - When `isPaused === false` and a tick arrives for `ticker`:
    - Computes `bucketTime` for `timeframe` (in seconds).
    - If `bucketTime === lastCandle.time`:
      - Updates `high`, `low`, `close`, `volume` in place.
      - Calls `initPriceSeriesRef.current.update(...)` in O(1).
      - Calls `initVolumeSeriesRef.current.update(...)` in O(1).
    - If `bucketTime > lastCandle.time`:
      - Initializes a new forming candle bar at `bucketTime`.
      - Calls `initPriceSeriesRef.current.update(...)` to append the new bar in O(1).
      - Calls `initVolumeSeriesRef.current.update(...)` in O(1).
  - This runs completely outside React's render loop — zero re-renders, <0.05ms per tick.

### 2. Guard React Subscriptions in `useChartData.ts` (PERF-01, PERF-03)
- In `useChartData.ts`:
  - When playback is active (`!isPaused && isReplayMode`), suppress reactive re-filtering:
    - `useChartData` does not need to recompute `filteredData` and `chartData` on every frame because the direct subscriber handles the forming candle live.
    - When playback pauses (or during manual seek/scrub), `currentTime` updates the state so all indicators / historical ranges sync up.
- Only recompute `chartData` on:
  - Initial load / ticker change / timeframe change / ETH toggle.
  - When paused and user scrubs or seeks to a new timestamp.

### 3. Decouple 1D Price Line in `useChartLifecycle.ts` (PERF-01)
- Remove `globalTime` React state selector from `useChartLifecycle.ts`.
- Update the 1D price line directly inside the playback subscriber or price line handler using `priceLineRef.current.applyOptions({ price })` without triggering component re-render.

### 4. Comprehensive Testing & Benchmarking
- Unit test in `tests/unit/playbackDecoupling.test.ts`:
  - Verify that rapid `currentTime` / `currentTick` dispatches do not trigger `useChartData` / `useChartLifecycle` re-renders while playing.
  - Verify `priceSeries.update()` is called with updated high/low/close in O(1).
  - Verify new candle bucket transition creates a new bar in O(1).
- Performance test verifying execution time < 0.1ms per tick.
