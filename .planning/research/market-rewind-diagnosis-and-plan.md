**Market Rewind: diagnosis and repair plan**

Investigated September 29, 2026, against commit `21bb84019e62a110f6d7d762fd57cbc27cf1db4b`. Scope: diagnosis and planning only. No application, repository test, configuration, or database changes were made. Diagnostic probes and this report are stored outside the repository.

The central problem is that the same replay time can produce different candles depending on how you reach it. Playback mutates a chart-local candle from the latest tick; pause and seek reconstruct candles from historical bars and tick slices; asynchronous loading can overwrite both the dataset and cursor. These paths disagree about volume, source coverage, symbol identity, and which history is already rendered. This explains why ordinary actions expose what look like unrelated edge cases.

**Evidence from the reported dates**

I read the running service through the existing development server's `/api` proxy. It reported healthy. The deployed service identifies candle responses as historical data; its response format differs from the repository's bundled Python service. The deployed API contract needs to be included in future integration tests.

| TSLA date | Historical 5-minute response | Premarket 5-minute bars on that date, 04:00–09:30 ET | Recorded ticks returned for 09:20 ET through end of date | Recorded ticks before 09:30 ET |
|---|---:|---:|---:|---:|
| September 22, 2026 | 1,500 bars | 66 | 12,199 | 2, at 09:22:42.921 and 09:24:24.113 |
| September 15, 2026 | 1,500 bars | 66 | 14,566 | 0; first tick at 09:30:00.085 |

The historical candles are marked MASSIVE and the raw ticks DATABENTO. Sparse recorded tick coverage is real in these responses. Missing raw ticks do not mean missing historical candles or a closed market. These requests establish available records, not the completeness of either provider's feed.

In the browser, September 22 at 09:20 showed approximately 41.16K volume before play and 5.29M by 09:20:17.547 in the candle fallback path. That run's replay buffer was empty despite separately successful API reads; the reason that particular browser request returned no ticks was not established.

September 15 loaded 1,373 derived intraday bars and 472 daily bars in this run. I did not reproduce the exact reported cold-load sequence that remains on one candle until refresh. I did reproduce a renderer condition that drops newly arriving history, described below.

**Confirmed defects and their connection to the symptoms**

1. **Volume grows on clock updates, and candle prices omit trades within a frame.** [The active chart subscriber](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartLifecycle.ts:485) handles every store notification as a trade and adds `tick.volume` again. It neither remembers which event it consumed nor aggregates all events crossed by [the replay clock](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/store/usePlaybackStore.ts:372). Repeating a 4-share tick across 60 clock updates produced volume 244. Crossing four ticks in one update produced H=105, L=100, V=5 instead of H=120, L=90, V=10. Different frame rates and speeds can therefore produce different candles. An unrelated store update can also recount the latest tick. This directly explains the rising volume and inconsistent candle formation.

2. **The historical fallback compounds the volume error and can expose future candle values.** [Fallback ticks](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/store/usePlaybackStore.ts:337) carry the entire minute's volume on every animation frame and label the result `STREAMING`. Two frames with a 1,000-volume minute produced 2,000 volume. Fallback selection uses the first tick in the global buffer, rather than coverage for each symbol. Before raw ticks begin, [the higher-timeframe reconstruction](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartData.ts:600) uses `localMasterData`, which is already 5-minute data for a TSLA 5-minute chart. It can include the completed 09:20–09:25 candle at 09:20:00. An isolated check showed its future high of 150 when only the open of 101 was known. The code also special-cases SPY for use of the global minute history, so symbols do not follow the same rules. Pausing and playing can consequently disagree even with identical inputs.

3. **History can be loaded into React state without being installed into the actual chart.** [Incremental rendering](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartLifecycle.ts:328) considers a dataset suitable for an incremental update if it contains the previously rendered last timestamp. It updates that candle and later candles but does not check whether earlier bars were added or changed. A controlled transition from one bar to two bars with the same last timestamp never installed the older bar. The DOM's `data-bars-count` describes React's derived array, so tests using that attribute can pass while the canvas lacks history. This is a concrete mechanism for the single-candle symptom, although its exact occurrence in the user's cold-load sequence remains unconfirmed.

4. **A chart with no initial candles cannot start rendering from the live path.** [The direct subscriber](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartLifecycle.ts:519) only creates or changes candles inside `if (lastCandle)`. After an empty history load finishes, incoming ticks still produce no first candle. Meanwhile, [the data hook intentionally freezes its snapshot while playing](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartData.ts:87). A new symbol's tick response arriving during playback also leaves that snapshot stale until pause. Time & Sales subscribes independently and can continue advancing. This is one concrete route to an updating tape with an empty or stale chart.

5. **Changing ticker can retain the previous company's prices.** [The history equality shortcut](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartData.ts:253) compares only array length and first/last timestamps. A TSLA-to-AAPL probe changed the label to AAPL but kept TSLA's price 100 instead of loading AAPL's 200 when timestamp ranges matched. Previous history is also left in state while new history loads. Separately, [adding symbol ticks](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/store/usePlaybackStore.ts:226) sorts the global buffer without repositioning `currentTickIndex`. The probe left `currentTick` at 09:31 while the buffer entry at its index was 09:30. The buffer has no ingestion deduplication, so concurrent requests can also insert the same records more than once.

6. **Old requests can overwrite a newer session.** [Session candle loading](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useMarketSimulator.ts:19) and [session tick loading](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/App.tsx:100) lack cancellation or a session-generation check before committing results. A controlled September 22 → September 15 switch, with the older response resolving last, put the replay clock back on September 22. Chart-level tick loading is keyed by symbol alone and accepts any existing ticks for that symbol, irrespective of date. The app and chart hook can request overlapping tick data independently. [History pagination](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartData.ts:275) also lacks a response-context guard and merges with the current history ref. These are confirmed code paths; exact user-visible outcomes depend on response order.

7. **Playback, seek, and visibility rules disagree.** The active intraday subscriber does not apply `showEth`, although static reconstruction filters extended-hours ticks. A diagnostic check showed a premarket tick added with ETH off. [Automatic viewport shifting is disabled](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/chart/useChartInit.ts:63), and the fast append path does not explicitly follow the replay head. Full replacements on ordinary seeks also skip viewport reconciliation unless another context condition is met. These viewport risks are established by code inspection; they were not exhaustively reproduced visually. Renderer exceptions are logged, but subsequent bookkeeping can still mark data hydrated, obscuring incomplete rendering.

8. **The scrubber's domain changes as you use it.** [Its bounds](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/components/PlaybackBar.tsx:46) come from buffered ticks plus the current cursor; when no ticks exist they come from the entire multi-day master history. In the browser, seeking September 15 to 09:34 changed the minimum from 09:20 to 09:30:00.085. Earlier premarket time became inaccessible through the slider. Its one-second step is anchored to that fractional minimum, so the requested 09:34 became 09:34:00.085. There is no exact-time entry, and [the slider shares at most 340 pixels with its labels](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/components/PlaybackBar.tsx:228). Every change immediately performs a seek and pauses. The difficulty reaching a specific time is an actual interaction-design problem in addition to the rendering defects.

9. **The tape is not proof that the selected chart's data advanced.** [Time & Sales](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/components/TimeAndSales.tsx:27) labels itself with a symbol but slices the global tick buffer without filtering by that symbol. The app includes default group symbols in its initial fetch even if those groups are unused. A multi-symbol session can therefore display another instrument's trades under the displayed symbol badge. This needs to be corrected alongside synchronization so the tape becomes a useful diagnostic signal.

**Why the current tests miss this**

Eight relevant existing test files passed all 32 tests. They cover incremental update calls, seeking, loading, single-candle responses, playback decoupling, real tick playback, premarket transition, and the time slider.

Eleven additional isolated diagnostic assertions failed against the current code. They cover repeated-volume counting, skipped intra-frame trades, omitted history, empty-chart startup, buffer cursor identity, fallback volume, ETH filtering, ticker price retention, future OHLC exposure, late tick hydration, and old-session response overwrite. These probes use the real hooks/store with mocked requests and chart APIs; they establish the logic failures but do not substitute for complete browser verification.

Several existing tests enforce performance behavior such as avoiding `setData()` without also verifying that all older bars and OHLCV remain correct. Others inspect React attributes rather than the actual series. The required missing invariant is: **for a given symbol, session, source policy, timeframe, and replay time, every route to that state must produce the same candles and volume.**

**Ordered repair plan — proposed work only**

1. **Preserve reproductions and define correctness before changing implementation.** Capture bounded fixtures from both dates, including candle/tick provenance and coverage. Add the isolated failures to the repository's proper test suites when implementation is authorized. Build an independent reference aggregator, plus diagnostics exposing session generation, per-symbol coverage, replay time, last consumed event, and actual rendered series count/last bar. Record errors instead of treating timeout, network failure, and successful empty data as the same condition. Exit criterion: each confirmed failure has a deterministic reproduction and expected output; no requirement to discover every possible click sequence manually.

2. **Make session and symbol data ownership explicit.** Introduce a session identity/generation, with per-symbol history, ticks, coverage, and load/error state. Route initial loads, ticker changes, and pagination through one request owner. Key requests by symbol, date/range, timeframe, source, and session filter. Cancel obsolete requests and reject late responses by generation. Use idempotent ingestion with a stable source event identity or page cursor; do not deduplicate solely by price/time because distinct trades can match. Reposition cursors after merges. Do not reset the replay clock merely because a symbol finishes loading. Exit criterion: response order, date changes, and adding symbols cannot replace another context's prices, move time, or duplicate volume.

3. **Unify candle construction and define the history/tick boundary.** Use one canonical aggregation engine for seek snapshots and live advancement. Consume every new tick exactly once; painting may be batched, event processing may not be skipped. Preserve provider provenance and select a documented source per interval. Do not add recorded ticks on top of a completed historical candle covering the same period. Do not assume two recorded premarket ticks constitute full market coverage. For missing tick intervals, use an explicit bar-replay policy; any intrabar estimate must be labelled, deterministic, and conserve the minute's volume. Completed historical OHLC must never masquerade as already-observed tick data in a forming candle. Load minute history per symbol, remove SPY-specific behavior, and share ETH/RTH/daily rules. Exit criterion: play, seek, pause, resume, stepping, and speed changes yield identical OHLCV at the same time within the declared source policy.

4. **Make the renderer reconcile the canonical result correctly.** Keep performance-oriented imperative chart updates, but make them consumers of the same canonical model. Use incremental updates only when the existing prefix is verified unchanged. Otherwise replace the series, including late history, corrected prices, backward seeks, or context changes. Reset identity, hydration, and last-candle state on session/date/symbol/timeframe changes. Support first-candle creation from an empty chart. Update price and volume consistently, and do not declare rendering complete after a series error. Follow the replay head while follow mode is active; preserve a manually panned viewport and clamp it when seeking removes its bars. Exit criterion: actual chart series match the canonical data, including historical prefixes and empty-to-populated transitions.

5. **Replace the moving scrubber domain with a stable session timeline.** Define fixed exchange-time session bounds and show data availability separately. Add `HH:MM:SS` entry, hover/drag time preview, 09:30/open and session-start shortcuts, and keyboard time stepping. Snap to exact time boundaries rather than the first tick's millisecond remainder. Preview during dragging and commit one seek on release/confirmation; pause consistently and resume only through an explicit playback action. Keep all chart and tape views on that committed cursor. Exit criterion: 09:34:00 is reachable exactly, 09:20 remains reachable after moving forward, and a late tick response cannot remap the slider.

6. **Verify the entire user journey against invariants.** Run controlled request-order tests and real browser journeys, then seeded random action sequences. Include play → seek forward/backward → resume → change ticker → change timeframe/ETH → change date → reload, in both the default 5m/1D layout and grouped/multi-symbol layouts. Exercise 0.5×, 1×, and 100× with different frame schedules. Inspect actual price and volume series, not just React data attributes. Ensure the tape filters or explicitly identifies symbols. Exit criterion: no stale-symbol prices, duplicated volume, future OHLC, lost history, uncaught chart errors, unexplained empty chart, or cursor/viewport disagreement across the matrix below.

| Scenario | Required outcome |
|---|---|
| TSLA September 22, 09:20 → 09:22 → 09:30 | Declared historical/tick policy; no frame-driven volume growth or discontinuous source double counting |
| TSLA September 15, 09:20 → 09:34 → play | Premarket history remains visible; no dependence on a refresh; daily candle uses only elapsed RTH data |
| Seek directly to T versus play to T | Same complete candle timestamps and OHLCV |
| Switch TSLA/AAPL after market open | Matching labels and prices; unchanged global time; complete elapsed new-symbol history |
| Old date resolves after new date | Old response discarded; new clock, history, and tape retained |
| Candle request fails while ticks succeed | Explicit partial-data/error state; ticks can create a first candle |
| One candle arrives before history | Final canvas installs the complete history regardless of matching final timestamp |
| ETH off during play and pause | Same filtering rules and same result |
| Empty, sparse, dense, delayed, and paginated tick sources | Coverage-aware behavior; stable timeline; no false closed-market conclusion |
| Pan/zoom, then seek backward/forward | Viewport follows the declared user/follow mode and never points into an empty invalid range |

The repair should proceed through these shared contracts rather than another collection of symptom-specific conditions. Steps 2–4 are the core stabilization work; the scrubber improvement and the broader journey checks should ship with that work before treating the simulator as reliable.
