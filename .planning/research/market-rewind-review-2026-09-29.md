**Findings, ordered by impact**

1. **[P1] Opening Time & Sales throws a React hook-order error.** [TimeAndSales.tsx:29](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/components/TimeAndSales.tsx:29) calls `usePlaybackStore` after `if (!isOpen) return null`, and also conditionally on the symbol. The app mounts this component with `isOpen=false`, then toggles it. A closed-to-open rerender throws `Rendered more hooks than during the previous render`. The app does not wrap this panel in its chart error boundary. Move the store subscription into the unconditional top-level hook sequence; test opening and closing the same mounted instance, plus symbol changes. Tests that independently mount an already-open panel cannot catch this.

2. **[P1] The new consumed-tick cursor is not synchronized with seeks or rendered snapshots.** [useChartLifecycle.ts:525](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartLifecycle.ts:525) starts `lastConsumedTimeRef` at zero and only advances it during active playback. It is neither initialized to the data already represented by a seek snapshot nor reset on rewind, date, symbol, or timeframe transitions. After mounting a sought candle that already contains two trades totalling volume 10, pressing Play immediately produces volume 20 without a new trade. In a separate rewind probe, the old consumed time/object suppresses ticks up to the previously visited point, leaving the rendered candle at volume zero despite replay crossing four trades. Establish the consumed event position as part of each snapshot/context transition and use a stable per-symbol event cursor. Resetting it blindly to zero would reproduce the first double-counting problem.

3. **[P1] The old-date request race remains in the session tick loader.** [App.tsx:146](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/App.tsx:146) still commits completed tick requests and restores their captured `targetMs` without a cancellation or generation check. The new generation guard exists only in `useMarketSimulator` for candle requests. I rendered the actual App with controlled tick promises: start September 22, switch to September 15, resolve September 15 first, then September 22. The final store time incorrectly becomes September 22 at 09:20. Apply the same session identity to all tick/candle/pagination commits and invalidate it when the session ends. The existing DIAG 11 covers only candle loading, so its passing result does not establish session-wide isolation.

4. **[P1] The look-ahead fix protects only the exact bar-start instant.** [useChartData.ts:643](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartData.ts:643) clips OHLC only when `bMs === effectiveCutoff`. One second later it includes that minute's completed high, low, and volume, even though the minute has not finished. Changing the original diagnostic from 09:20:00 to 09:20:01 exposes the completed high 105 instead of the currently known high 101. This also applies to the higher-timeframe fallback when minute history for the selected symbol is absent. Handle the entire forming interval, not timestamp equality: completed bars must have ended by the replay cursor; any partial-bar model must obey the explicitly chosen estimation policy.

5. **[P2] Synthetic fallback volume now replaces the whole higher-timeframe volume with one minute's volume.** [useChartLifecycle.ts:601](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartLifecycle.ts:601) assigns `lastCandle.volume = tickVol`. This prevents unlimited compounding but discards earlier minutes within a 5-minute/hour/day candle. A 1,000-volume minute followed by a 200-volume minute makes the same 5-minute candle fall to 200. Track completed constituent volume separately from the current constituent's partial volume, or derive both paths from one canonical aggregate. Also note that synthesized ticks produced by `seekTickTime` still do not receive the new `isSynthesized` flag.

6. **[P2] The slider still loses its premarket range after seeking.** [PlaybackBar.tsx:46](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/components/PlaybackBar.tsx:46) still derives its domain from the first buffered tick plus `currentTime`. Rounding those values fixes the fractional-second problem, not the moving-domain problem. With session start 09:20 and first tick 09:30:00.085, seeking to 09:34 moves the minimum from 09:20 to 09:30. This reproduced in a component test. The new exact-time field is useful, but the slider must use persisted session bounds independently of the cursor and loaded tick range.

7. **[P2] New tick aggregation rescans the entire day's ticks on every frame.** [useChartLifecycle.ts:527](/Users/emadarshadalam/Documents/GitHub/market-rewind/src/hooks/useChartLifecycle.ts:527) iterates all `symbolTicks` and parses every timestamp on every store update, including clock-only frames; it does not stop after reaching future ticks. At 100,000 ticks, 60 updates/second and two charts, this is roughly 12 million timestamp parses/second. This cost is established from the loop structure, not a measured wall-clock slowdown in this review. Use a binary-searched starting cursor on seek and advance only through newly elapsed events during play. Preserve distinct events with equal timestamps. The new tape filtering similarly scans the global buffer to obtain counts on each subscribed update and should use per-symbol indexing.

8. **[P2] The new browser tape test can pass without testing the tape at all.** [10-diagnostic-defects.spec.ts:42](/Users/emadarshadalam/Documents/GitHub/market-rewind/tests/regression/journey/10-diagnostic-defects.spec.ts:42) only checks rows if the tape is already visible; `beginReplay` never opens it and the app defaults it closed. It can therefore pass with zero row assertions and never encounter finding 1. Even when open, rows show prices/time/size, not ticker names, so checking that text lacks `AAPL` cannot prove symbol isolation. Explicitly open the panel, require nonempty rows, feed distinct per-symbol prices, and assert their inclusion/exclusion while switching the selected chart. The slider browser test also needs a fixture whose first tick is after session start; otherwise moving bounds remain undetected.

**Deployment and completion-status discrepancy**

Removing `historical.duckdb` from the bundled Python service does not change the separate service the frontend is using. Both configured frontend URLs still point to port 8420 on the existing data service; the bundled server defaults to port 8765. A request to the configured service for TSLA September 22 candles returned `database: historical` and `source: MASSIVE`. Thus the running configuration does not yet demonstrate the advertised streaming-only contract. Do not silently switch endpoints as part of a review; explicitly verify/deploy the intended service and exercise the frontend against it during the next implementation step.

Even within one database, the shared candle-construction requirement is not implemented: paused reconstruction remains in `useChartData`, active mutation remains in `useChartLifecycle`, and synthetic fallback remains in `usePlaybackStore`. A database-source change cannot by itself make these paths agree. The milestone audit's claims of fixed session bounds, comprehensive cancellation, immediate old-candle flushing, and complete defect elimination are broader than the implementation and test evidence support.
